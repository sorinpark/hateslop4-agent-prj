## 3. 아키텍처 전환 — 로컬 웹캠 → 브라우저 실시간 (2026-07-04 결정)

**배경**: 최종 발표에서 여러 사용자가 각자 브라우저로 접속해 체험해야 함.
현재 `spike_webcam.py`는 Python이 로컬 컴퓨터의 웹캠을 직접 여는 구조라
"실행하는 컴퓨터의 카메라"만 쓸 수 있고, 여러 사용자가 각자 접속하는
서비스로는 확장 불가. `spike_webcam.py`는 폐기하지 않고 원래 목적대로
개발자 개인 실험/검증용 스크립트로 유지하고, 별도로 프로덕션 경로를 신설한다.

- 브라우저(React)가 웹캠을 열고 MediaPipe JS로 랜드마크 추출 → WebSocket으로 서버 전송

  기존 `angles.py`/`feature_extractor.py` 로직 재사용 → `FeatureSummary` →
  `feedback_svc.create_feedback` 호출 → 결과를 같은 WebSocket으로 클라이언트에 push

  session_id 기준으로 accumulator 격리 필수

## 5. 추후 리서치 과제 (2026-07-05 논의)

카메라 가드/실시간 화면에서 관절 인식이 잘 안 되는 경우(어두운 옷, 역광,
어두운 배경 등) 관련해서 "사용자가 관절 위치를 수동으로 찍어서 보완하면
어떨지" 논의했으나, 아래 이유로 지금 범위에서는 채택하지 않기로 함:
- MediaPipe는 좌표 힌트를 입력받는 구조가 아니고, 이전 프레임 기반 추적을
  이미 내부적으로 하고 있어 수동 입력이 추가 정보를 주지 못함
- 근본 원인은 "관절 위치를 모르는 것"이 아니라 "픽셀 자체가 배경/옷과
  구별 안 되는 것"이라 위치 힌트로 해결되지 않음
- 정지 이미지 좌표 지정으로는 실시간(초당 ~30프레임) 추적을 대체할 수 없음

**현재 채택한 대응**: 실시간 스켈레톤 오버레이로 어떤 관절이 인식 안 되는지
사용자에게 보여주고, 조명/옷/카메라 위치를 스스로 조정하게 함. 서버의
Confidence.below_threshold 가드가 나쁜 데이터 기반 피드백을 막아줌.

**추후(이번 5주 프로젝트 범위 밖) 고려 가능한 방향**: 다른 포즈 모델
비교, IR/저조도 카메라 활용 등 — 지금은 리서치 안 함.

### 알아둘 운영 이슈 (07-07)
- **`uvicorn --reload` 고아 프로세스**: reload worker가 부모 죽은 뒤에도 8000을
  점유해 옛 코드로 응답하는 경우 관측됨(모델 변경이 반영 안 돼 혼란). 코드 바꾸고
  반영이 이상하면 8000 포트를 완전히 정리 후 재시작할 것. (테스트 땐 `--reload` 빼는 것도 방법)
- **Gemini 무료 quota**: 실시간 피드백이 5초마다 LLM을 호출해 요청 수를 많이 씀.
  하루 많이 테스트하면 429(quota) 소진 가능. `gemini-flash-lite-latest`가 여유가
  크지만, 추후 "피드백 호출 주기 늘리기/조건부 호출"로 소비를 줄이면 좋음.
