`feat/backend`(또는 `main`)를 먼저 merge/rebase한 뒤 다시 push해야 안전하게 merge 가능.

   — 이게 안 끝나면 이후 작업이 옛날 백엔드 코드 위에서 진행되는 셈이라 다시 꼬임 (여유되는 쪽이 처리)
2. **[트랙 A · dokong22222] 스파이크 → 실제 특징 추출로 전환** — ✅ 완료
   — `spike_webcam.py`를 계약 ②(`schemas.FeatureSummary`) 형식으로 실제 출력하도록 확장
3. **[트랙 B · 효주] `/feedback` 실연동** — ✅ 완료
   — `profile.py`가 쓴 패턴(system_instruction + response_schema)을 그대로 따라
     `feedback.py` 신설 → `main.py`의 하드코딩 블록을 실제 호출로 교체
4. **[트랙 A · dokong22222] SQLite 스키마 설계 + 프론트 목 JSON → 실제 API 교체** — 🟡 스키마·저장 로직은 ✅, 프론트 API 교체는 ❌ (프론트 merge 대기 중)
   — 트랙 B의 응답 형식(`FeedbackResponse`)이 이미 `schemas.py`에 확정돼 있으므로 지금 바로 시작 가능
5. **[둘 다] 동기화 포인트** — 트랙 A가 실제 `FeatureSummary`를 처음 뽑으면 트랙 B에게 5분 공유 →
   트랙 B가 실제 `FeedbackResponse`를 처음 뽑으면 다시 공유 → 둘이 웹캠부터 화면까지 한 번 통으로 실행
   → ✅ 완료 (양쪽 다 실제 값 뽑는 단계까지는 됨). 남은 건 **웹캠→POST /feedback→화면**까지 실제로 잇는 것
